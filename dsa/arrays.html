The idea

A row of numbered seats

Think of a cinema row with seats numbered 0, 1, 2, … To find seat 14 you walk straight to it; you don't check seats 0 to 13 first. But if a latecomer needs to sit in seat 3 and everyone must stay in order, every person from seat 3 onward has to shuffle one seat right. That is an array: instant access by position, expensive inserts in the middle.

An array stores items in one continuous block of memory. Because every slot is the same size, the computer finds slot i with arithmetic instead of searching:

address of arr[i] = start + i × slot_size

 index:   0     1     2     3     4
        ┌─────┬─────┬─────┬─────┬─────┐
 value: │  7  │  2  │  9  │  4  │  5  │   ← one continuous block
        └─────┴─────┴─────┴─────┴─────┘
        start                  start + 4 × size

A Python list is a dynamic array. It reserves extra space, and when it fills up it moves everything into a block about 1.125–2× bigger. That move costs O(n), but it happens so rarely that append averages out to O(1). This averaging is called amortized cost.

Amortized cost is like moving house. Moving takes a whole weekend, but if you only move when your family doubles in size, the cost per new family member stays small.

Patterns

Six patterns that solve most array problems

1. Hashmap complement lookup

O(n) time · O(n) space

At a party you need someone whose height plus yours equals 340 cm. Instead of comparing yourself with every guest, you write your height on a board as you arrive. Each newcomer checks the board for "340 minus my height." The first match is instant.

Use whenyou need a pair (or earlier element) that satisfies a condition with the current element.

def two_sum(nums, target):
    seen = {}                       # value -> index
    for i, x in enumerate(nums):
        if target - x in seen:      # O(1) lookup
            return [seen[target - x], i]
        seen[x] = i                 # store AFTER checking (no self-pairing)

2. Two pointers from both ends

O(n) after sorting · O(1) space

Two friends balance a seesaw using weights lined up from lightest to heaviest. One starts at the light end, one at the heavy end. Too heavy? The heavy-side friend steps toward lighter weights. Too light? The light-side friend steps up. They meet in the middle having checked every useful combination.

Use whenthe array is sorted (or you can sort it) and you're looking for pairs, or when the answer depends on two ends shrinking inward.

def pair_with_sum(nums, target):   # nums sorted
    l, r = 0, len(nums) - 1
    while l < r:
        s = nums[l] + nums[r]
        if s == target: return (l, r)
        if s < target: l += 1       # need bigger
        else: r -= 1                 # need smaller
    return None

3Sum = fix one number, then run this on the rest: O(n²). Container With Most Water = always move the shorter wall, because moving the taller one can never help.

3. Prefix sums

O(n) build · O(1) per range query

Highway mile markers. To know the distance from exit 12 to exit 40 you don't add up every mile between them; you subtract the markers: 40 − 12. A prefix-sum array is a row of mile markers for your data.

Use whenthe problem asks about sums of contiguous subarrays, especially "how many subarrays sum to k."

# sum(nums[l..r]) == pre[r+1] - pre[l]
pre = [0]
for x in nums: pre.append(pre[-1] + x)

# Subarray Sum Equals K: prefix sum + hashmap of counts
def subarray_sum(nums, k):
    count, run, seen = 0, 0, {0: 1}   # empty prefix seen once
    for x in nums:
        run += x
        count += seen.get(run - k, 0)  # earlier prefix that makes a k-sum
        seen[run] = seen.get(run, 0) + 1
    return count

Why not sliding window here? Negative numbers break it: growing the window can make the sum smaller. Prefix sums don't care about signs.

4. Kadane's algorithm

O(n) time · O(1) space

You run a lemonade stand and track daily profit. If your running total ever goes negative, carrying it forward only hurts tomorrow, so you "start a new business" from today. Kadane's keeps the best streak ever seen while doing exactly that.

Use whenyou need the best (max/min) contiguous subarray.

def max_subarray(nums):
    cur = best = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)   # extend, or restart at x
        best = max(best, cur)
    return best

5. In-place marking (index as a hash)

O(n) time · O(1) extra space

A hotel with rooms 1 to n. Each guest holding key k walks to room k. Afterwards you walk the corridor: the first empty room is the smallest missing key. You used the rooms themselves as the record, with no extra notebook.

Use whenvalues lie in the range 1..n and you're asked for O(1) extra space (First Missing Positive, find duplicates), or you must record flags inside a matrix (Set Matrix Zeroes uses row 0 and column 0 as flags).

def first_missing_positive(nums):
    n = len(nums)
    for i in range(n):
        # keep swapping nums[i] into its "room" nums[i]-1
        while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
            j = nums[i] - 1
            nums[i], nums[j] = nums[j], nums[i]
    for i in range(n):
        if nums[i] != i + 1: return i + 1
    return n + 1

The while loop looks like O(n²), but each swap puts one number in its final room, so there are at most n swaps total: O(n).

6. Matrix traversal with boundaries

O(rows × cols)

Mowing a rectangular lawn in a spiral: mow the top edge, the right edge, the bottom, the left, then the lawn left to mow is a smaller rectangle. Each lap shrinks four boundaries by one.

Use whenyou walk a grid in a fixed shape (spiral, diagonal, layers) or rotate it.

def spiral(m):
    res = []
    top, bot, left, right = 0, len(m) - 1, 0, len(m[0]) - 1
    while top <= bot and left <= right:
        for c in range(left, right + 1): res.append(m[top][c])
        top += 1
        for r in range(top, bot + 1): res.append(m[r][right])
        right -= 1
        if top <= bot:
            for c in range(right, left - 1, -1): res.append(m[bot][c])
            bot -= 1
        if left <= right:
            for r in range(bot, top - 1, -1): res.append(m[r][left])
            left += 1
    return res

The two if checks stop a single leftover row or column from being read twice. That is the most common bug in this problem.

Deep analysis

Trapping Rain Water, from brute force to optimal

Picture a city skyline after a storm. Water sitting on top of a building can only rise as high as the shorter of the tallest building to its left and the tallest building to its right. Any higher and it spills over the lower side.

So the water above bar i is min(maxLeft, maxRight) − height[i]. The whole problem is about computing those two maxima cheaply.

Brute force, O(n²) time, O(1) space. For each bar, scan left and right for the maxima. Correct, but 10⁵ bars means 10¹⁰ steps.

Precompute, O(n) time, O(n) space. Build leftMax[i] in one pass from the left and rightMax[i] in one pass from the right, then sum. Classic space-for-time trade.

Two pointers, O(n) time, O(1) space. Key insight: if leftMax < rightMax, the left bar's water is decided by leftMax alone, because some bar on the right is at least that tall. So process whichever side has the smaller max and move inward.

def trap(h):
    l, r = 0, len(h) - 1
    lmax = rmax = water = 0
    while l < r:
        if h[l] < h[r]:
            lmax = max(lmax, h[l]); water += lmax - h[l]; l += 1
        else:
            rmax = max(rmax, h[r]); water += rmax - h[r]; r -= 1
    return water

Walking an interviewer through all three versions, in this order, is exactly what Google wants to see: a correct baseline, a named trade-off, then the insight that removes the trade-off.

Before you say "done"

Edge cases to test

A pilot's pre-flight checklist exists because experts skip obvious things under pressure. Run this list out loud on every array problem.

  • Empty array, and a single element.
  • All elements the same; all negative (breaks naive "max starts at 0").
  • Duplicates (3Sum must skip them).
  • Already sorted, and reverse sorted.
  • Integer overflow doesn't happen in Python, but mention it if the interviewer is thinking in Java or C++.
  • Off-by-one at the boundaries: range(n) vs range(n - 1), l < r vs l <= r.
