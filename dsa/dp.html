Algorithms

Recursion, backtracking, and dynamic programming

These three are one idea at different speeds: break a problem into smaller copies of itself. Backtracking tries every choice; DP notices the same subproblems repeat and remembers their answers.

The idea

Don't solve the same thing twice

Someone writes "1 + 1 + 1 + 1 + 1 + 1 + 1" on a board and asks the total. You count: 7. Then they add "+ 1" and ask again. You don't recount; you say 8, because you remembered 7. That's dynamic programming: store answers to smaller problems so bigger ones are a single step.

fib(5) without memory             fib(5) with memory
              f5                      f5 → f4 → f3 → f2 → f1
            /    \                         ↘    ↘    ↘
          f4      f3                       (each f computed once,
         /  \    /  \                       later calls are lookups)
       f3   f2  f2  f1
      / \                             O(2ⁿ) calls  →  O(n) calls
    f2  f1   ← f3 computed twice, f2 three times
Recursion first

Every recursive function has two parts

A line of people asking "what row am I in?" Each person asks the person in front and adds 1. The person in the front row knows the answer without asking: that's the base case. Without it, the question is passed forward forever.

  1. Base case: the smallest input you can answer directly.
  2. Recursive case: express the answer using the same function on a smaller input.

Trust that the smaller call works (the "recursive leap of faith"), and check only that each call moves toward the base case.

Patterns

Six patterns from brute force to DP

1. Backtracking: choose, explore, un-choose

O(2ⁿ) subsets · O(n!) permutations

Trying on outfits. Put on a shirt (choose), try every pants option with it (explore), take the shirt off (un-choose), and try the next shirt. Taking the shirt off is what lets you reuse the same body for the next combination.

Use whenthe problem says "all": all subsets, permutations, combinations, partitions, or board placements.

def subsets(nums):
    res, path = [], []
    def go(i):
        if i == len(nums):
            res.append(path[:]); return         # copy!
        path.append(nums[i]); go(i + 1)      # choose nums[i]
        path.pop();           go(i + 1)      # un-choose, skip it
    go(0)
    return res

def combination_sum(cands, target):
    res, path = [], []
    def go(start, remain):
        if remain == 0: res.append(path[:]); return
        for i in range(start, len(cands)):
            if cands[i] > remain: continue        # prune
            path.append(cands[i])
            go(i, remain - cands[i])           # i, not i+1: reuse allowed
            path.pop()
    go(0, target)
    return res

2. Memoization (top-down DP)

O(states × work per state)

A tax accountant with a filing cabinet. Before calculating a client's deduction, they check whether it's already in the cabinet. Same recursion as before, plus a cabinet.

Use whenyou've written a correct recursive solution and the same arguments repeat.

from functools import cache
def climb_stairs(n):
    @cache                          # the filing cabinet
    def ways(i):
        if i <= 1: return 1
        return ways(i - 1) + ways(i - 2)
    return ways(n)

3. Tabulation (bottom-up DP)

Same time, no recursion

Building a staircase from the ground up: you can't place step 5 until steps 1 to 4 exist. A table filled in order means every answer you need is already there when you get to it.

Use whenthe order of subproblems is clear; it avoids recursion limits and often allows space savings.

def coin_change(coins, amount):
    INF = float('inf')
    dp = [0] + [INF] * amount             # dp[a] = fewest coins for a
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != INF else -1

4. 1D DP: take it or skip it

O(n) time · O(1) space

A burglar on a street can't rob two neighboring houses without setting off alarms. At each house the choice is: rob it plus the best from two houses back, or skip it and keep the best from one house back.

Use wheneach item's decision depends only on the last one or two decisions.

def rob(nums):
    prev2 = prev1 = 0                     # best up to i-2, i-1
    for x in nums:
        prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1

House Robber II (houses in a circle): run this twice, once without the first house and once without the last, and take the max.

5. 2D DP on two sequences or a grid

O(m × n)

Comparing two versions of a document (like Git's diff). You line one version along the top of a table and the other down the side; each cell answers "how similar are these two prefixes?" and builds on the cells above and to the left.

Use whenthere are two strings (LCS, Edit Distance) or a grid (Unique Paths, min path sum).

def lcs(a, b):
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i-1] == b[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1          # match: diagonal + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])  # drop one letter
    return dp[m][n]

6. 0/1 knapsack

O(n × capacity)

Packing a carry-on with a 7 kg limit. Each item either goes in once or doesn't. For every possible weight from 7 down to 0, you ask: is it better with this item or without it?

Use wheneach item is used at most once and you're hitting a target sum or capacity (Partition Equal Subset Sum, Target Sum).

def can_partition(nums):
    total = sum(nums)
    if total % 2: return False
    target = total // 2
    dp = [True] + [False] * target       # dp[s]: can some subset make s?
    for x in nums:
        for s in range(target, x - 1, -1):  # BACKWARDS: use x once
            dp[s] = dp[s] or dp[s - x]
    return dp[target]

Loop backwards for "each item once" (0/1 knapsack). Loop forwards for "unlimited copies" (Coin Change). Mixing these up is the most common knapsack bug.

Method

The five-step DP recipe

Like writing a recipe card: what dish (state), the basic step (transition), what you start with (base case), the order you cook (iteration order), and what you serve (the answer cell).

State: what does dp[i] (or dp[i][j]) mean, in one sentence? "dp[a] = fewest coins to make amount a."

Transition: how does a state use smaller states? "dp[a] = min over coins c of dp[a − c] + 1."

Base cases: the states you know without computing. "dp[0] = 0."

Order: fill so dependencies come first (small a to large a; top-left to bottom-right).

Answer: which cell, and what if it's unreachable? "dp[amount], or −1 if it's still infinity."

Say the state definition out loud before writing code. Most DP bugs are a fuzzy state definition, and interviewers will often accept a correct memoized solution even if you never convert it to a table.

Deep analysis

Longest Increasing Subsequence, two ways

Stacking boxes by size: you go through boxes in the order they arrived and want the tallest tower where each box is bigger than the one below. You can skip boxes but can't reorder them.

O(n²) DP. dp[i] = length of the longest increasing subsequence ending at index i. For each i, look at every earlier j with nums[j] < nums[i].

def lis(nums):
    dp = [1] * len(nums)
    for i in range(len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

O(n log n) patience sorting. Keep tails[k] = the smallest possible tail of an increasing subsequence of length k+1. For each number, binary-search the first tail ≥ it and replace it (or append).

import bisect
def lis_fast(nums):
    tails = []
    for x in nums:
        i = bisect.bisect_left(tails, x)
        if i == len(tails): tails.append(x)
        else: tails[i] = x                  # a smaller tail is never worse
    return len(tails)

The card game Patience: deal cards onto piles, always placing a card on the leftmost pile whose top card is bigger or equal. The number of piles you end with is the LIS length.

tails is not itself a valid subsequence; only its length is meaningful. Interviewers like asking that.

Before you say "done"

Edge cases and pitfalls

A recipe that fails for zero guests or one guest isn't a recipe. Test the tiny inputs first.

  • Empty input, n = 0 or 1, amount = 0.
  • Unreachable states: initialize with infinity, and convert back to −1 at the end.
  • Appending path instead of path[:] in backtracking: every result ends up empty.
  • Recursion depth over 1,000: switch to tabulation, or raise the limit with sys.setrecursionlimit.
  • Duplicates in input for subsets/permutations: sort, then skip equal neighbors at the same depth.
