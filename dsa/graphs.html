The idea

Cities and roads

Google Maps is a graph: intersections are nodes (vertices), roads are edges. One-way streets are directed edges; travel times are edge weights. Friend networks, flight routes, course prerequisites, and web links are all graphs too. A tree is just a graph with no cycles where every node has one parent.

for a, b in edges:          # undirected: add both directions

Grids are graphs too. Each cell is a node; its up/down/left/right neighbors are edges. You don't build a list; you compute neighbors with for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)).

Patterns

Six graph templates

1. BFS (shortest path, unweighted)

O(V + E)

Spreading news through friends: day 1 your friends hear it, day 2 their friends, and so on. The first day someone hears it is their shortest distance from you. BFS explores in exactly these rings.

Use when"shortest," "minimum steps," or "nearest" in an unweighted graph or grid.

from collections import deque
def bfs(start, graph):
    dist = {start: 0}
    q = deque([start])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:               # mark when QUEUED, not when popped
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

2. DFS (explore everything reachable)

O(V + E)

Exploring a cave system with a ball of string: follow one tunnel as deep as it goes, back up to the last junction, try the next tunnel. The string (recursion stack) lets you find your way back.

Use whencounting components, flood fill, cloning, path existence, cycle detection.

def num_islands(grid):
    R, C = len(grid), len(grid[0])
    def sink(r, c):
        if not (0 <= r < R and 0 <= c < C) or grid[r][c] != '1':
            return
        grid[r][c] = '0'                     # mark visited
        sink(r+1, c); sink(r-1, c); sink(r, c+1); sink(r, c-1)
    count = 0
    for r in range(R):
        for c in range(C):
            if grid[r][c] == '1':
                count += 1; sink(r, c)
    return count

Ask before mutating the input grid. If not allowed, use a visited set. For huge grids, iterative BFS avoids Python's recursion limit.

3. Multi-source BFS

O(V + E)

Several fires start at once in a forest. Each minute every fire spreads one tree further. Instead of simulating each fire separately, you light them all at minute 0 by putting every source in the queue together.

Use whenseveral starting points spread simultaneously (Rotting Oranges, Walls and Gates, distance to nearest X).

def oranges_rotting(grid):
    R, C = len(grid), len(grid[0])
    q = deque((r, c) for r in range(R) for c in range(C) if grid[r][c] == 2)
    fresh = sum(row.count(1) for row in grid)
    minutes = 0
    while q and fresh:
        for _ in range(len(q)):                # one minute = one level
            r, c = q.popleft()
            for nr, nc in ((r+1,c),(r-1,c),(r,c+1),(r,c-1)):
                if 0 <= nr < R and 0 <= nc < C and grid[nr][nc] == 1:
                    grid[nr][nc] = 2; fresh -= 1; q.append((nr, nc))
        minutes += 1
    return minutes if fresh == 0 else -1

4. Topological sort

O(V + E)

Getting dressed: socks before shoes, shirt before jacket, but socks and shirt in any order. A topological order is any valid dressing sequence. If the rules say "shoes before socks" and "socks before shoes," there's a cycle and no valid order exists.

Use whenthere are dependencies/prerequisites: course schedules, build order, alien dictionary.

def can_finish(n, prereqs):
    graph, indeg = defaultdict(list), [0] * n
    for course, pre in prereqs:
        graph[pre].append(course); indeg[course] += 1
    q = deque(i for i in range(n) if indeg[i] == 0)
    taken = 0
    while q:
        u = q.popleft(); taken += 1
        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0: q.append(v)
    return taken == n          # fewer means a cycle

5. Union-find (disjoint set union)

≈ O(1) per operation

Merging companies. Every company has a CEO. When two companies merge, one CEO reports to the other. To check whether two employees now work for the same group, follow each one's chain of bosses to the top and compare. Path compression is every employee learning the top CEO's name directly so the next lookup is one step.

Use whenedges arrive one by one and you ask "are these connected?" or "does this edge make a cycle?" (Redundant Connection, Number of Connected Components, Kruskal's MST).

class DSU:
    def __init__(self, n):
        self.parent, self.size = list(range(n)), [1] * n
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # path compression
            x = self.parent[x]
        return x
    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb: return False                     # already connected → cycle
        if self.size[ra] < self.size[rb]: ra, rb = rb, ra
        self.parent[rb] = ra; self.size[ra] += self.size[rb]  # union by size
        return True

6. Dijkstra (shortest path, weighted)

O((V + E) log V)

Planning the fastest drive home. You always extend the closest unexplored intersection first, the way water flowing from your house would reach the nearest corners first. Once an intersection is reached the first time, that's its fastest time, as long as no road has negative travel time.

Use whenedges have non-negative weights and you need the cheapest/fastest path (Network Delay Time, Cheapest Flights, Swim in Rising Water).

import heapq
def dijkstra(src, graph):                # graph[u] = [(v, w), ...]
    dist = {src: 0}
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float('inf')): continue   # stale entry
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float('inf')):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

Choosing

Which template?

Like choosing transport: walking for a short trip, a train for a fixed route, a plane for long distances. Match the template to what the question asks.

Deep analysis

Word Ladder: BFS where the graph is hidden

A word game where you change one letter at a time and every step must be a real word: COLD → CORD → CARD → WARD → WARM. You don't get a map; you discover neighbors as you go.

Spot the graph. Each word is a node; two words connect if they differ by one letter. "Fewest transformations" = shortest path in an unweighted graph = BFS.

Don't build all edges. Comparing every pair is O(N² · L). Instead, for each word generate its L × 25 one-letter variations and check them against a set: O(N · L · 26).

Remove words from the set when queued so nobody visits them again (same as marking visited).

Optional speed-up: bidirectional BFS from both ends, always expanding the smaller frontier. Mention it; you rarely need to code it.

def ladder_length(begin, end, word_list):
    words = set(word_list)
    if end not in words: return 0
    q, steps = deque([begin]), 1
    while q:
        for _ in range(len(q)):
            w = q.popleft()
            if w == end: return steps
            for i in range(len(w)):
                for ch in 'abcdefghijklmnopqrstuvwxyz':
                    nxt = w[:i] + ch + w[i+1:]
                    if nxt in words:
                        words.remove(nxt); q.append(nxt)
        steps += 1
    return 0

Google loves graphs that aren't drawn for you: words, board states, lock combinations. Say "I'll model this as a graph where nodes are… and edges are…" before anything else.

Before you say "done"

Edge cases to test

A delivery driver's route planner has to cope with an address on an island with no road, and with a one-way loop that never ends.

  • Disconnected graph: loop over all nodes, not just node 0.
  • Cycles: always track visited, or you loop forever.
  • Self-loops and duplicate edges.
  • Directed vs undirected: ask. Adding both directions to a directed graph is a classic bug.
  • Grid boundaries: check bounds before indexing.
  • Unreachable target: return -1 or infinity as the problem says.
