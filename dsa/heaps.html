Heaps and priority queues

A heap always hands you the smallest (or largest) item in O(log n), without sorting everything. Whenever a problem says "top k," "k-th largest," "closest," or "merge sorted," think heap.

The idea

A hospital emergency room

An emergency room doesn't serve patients in arrival order. The most urgent patient is always seen next, and new arrivals slot in according to urgency. Nobody keeps the whole waiting room perfectly sorted; staff only need to know who's most urgent right now. That's a priority queue, and a heap is how it's built.

A min-heap is a complete binary tree where every parent is ≤ its children, so the minimum is at the root. It's stored in a plain array: the children of index i are at 2i + 1 and 2i + 2, and its parent is at (i − 1) // 2.

          1                 array: [1, 3, 8, 5, 4]
        /   \               index:  0  1  2  3  4
       3     8
      / \                   children of 1 (index 1): indices 3, 4 → 5, 4
     5   4                  parent of 4 (index 4): (4−1)//2 = 1 → 3

Python only has a min-heap. For a max-heap, push negated values (-x) and negate again when popping. For objects, push tuples: (priority, tiebreaker, item).

Patterns

Five heap patterns

1. Top K with a size-k min-heap

O(n log k) time · O(k) space

A talent show keeps only 3 chairs for finalists. When a new act beats the weakest finalist, the weakest leaves and the new act sits down. The chairs are a min-heap of size 3, so the weakest finalist is always easy to find.

Use whenyou need the k largest (use a min-heap) or k smallest (use a max-heap) items.

import heapq
def find_kth_largest(nums, k):
    h = []
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k: heapq.heappop(h)     # evict the weakest
    return h[0]                             # k-th largest

Why a min-heap for the largest? Because you need to throw away the smallest of your current top k quickly.

2. Count, then heap by frequency

O(n log k)

A music app's "your top 5 songs this year": first count plays per song, then keep only the five most played.

Use whenthe ranking is by how often something appears.

from collections import Counter
def top_k_frequent(nums, k):
    cnt = Counter(nums)
    return heapq.nlargest(k, cnt.keys(), key=cnt.get)

O(n) alternative: bucket sort by frequency (index = count, holding the values with that count), then read buckets from high to low.

3. K-way merge

O(N log k), N = total items

Merging k sorted checkout lines into one: look only at the person at the front of each line, send the earliest arrival through, and the next person in that line steps up. The heap holds just the k front-runners.

Use whenmerging k sorted lists, k-th smallest in a sorted matrix, or smallest pairs across arrays.

def merge_k_lists(lists):
    h = [(node.val, i, node) for i, node in enumerate(lists) if node]
    heapq.heapify(h)
    dummy = tail = ListNode()
    while h:
        _, i, node = heapq.heappop(h)          # i breaks ties (nodes aren't comparable)
        tail.next = tail = node
        if node.next: heapq.heappush(h, (node.next.val, i, node.next))
    return dummy.next

4. Two heaps for a running median

O(log n) add · O(1) median

Splitting a class into a short half and a tall half for a photo. The tallest of the short half and the shortest of the tall half stand in the middle. Each new student joins one half, and if the halves get uneven, one person switches sides.

Use whenyou need the median of a growing stream.

class MedianFinder:
    def __init__(self):
        self.lo, self.hi = [], []          # lo: max-heap (negated), hi: min-heap
    def addNum(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))   # keep lo ≤ hi
        if len(self.hi) > len(self.lo):                     # rebalance
            heapq.heappush(self.lo, -heapq.heappop(self.hi))
    def findMedian(self):
        if len(self.lo) > len(self.hi): return -self.lo[0]
        return (-self.lo[0] + self.hi[0]) / 2

5. Greedy scheduling with a heap

O(n log n)

A barista with a cooldown rule (the same drink can't be made twice in a row within n orders) always makes the most-ordered drink that's allowed right now, so the long queue for lattes doesn't end up stuck at the end.

Use whenyou repeatedly pick the "biggest remaining" item under a constraint (Task Scheduler, Reorganize String, meeting rooms).

def reorganize_string(s):
    h = [(-c, ch) for ch, c in Counter(s).items()]
    heapq.heapify(h)
    out, prev = [], None                      # prev = item cooling down
    while h:
        c, ch = heapq.heappop(h)
        out.append(ch)
        if prev: heapq.heappush(h, prev)
        prev = (c + 1, ch) if c + 1 < 0 else None
    return "".join(out) if len(out) == len(s) else ""
Deep analysis

Kth Largest: heap vs sort vs quickselect

Finding the 10th fastest runner among 50,000 marathon finishers. You could rank everyone (sort), keep a short list of the 10 fastest so far (heap), or repeatedly split the field around a random runner's time until the 10th lands in place (quickselect).

ApproachTimeSpaceWhen to pick it
Sort and indexO(n log n)O(n) or O(1)Simplest; fine as a first answer
Size-k min-heapO(n log k)O(k)Streaming data, or k much smaller than n
QuickselectO(n) average, O(n²) worstO(1)One-off query on an array you may modify

Give the heap answer, then mention quickselect and its worst case. Saying "if the data were a stream, only the heap works" shows you're thinking about real systems, which Google values.

Before you say "done"

Edge cases and pitfalls

In an ER, two patients with the same urgency still need a fair rule for who goes first. Heaps need tie-breakers too.

  • Tuples with equal priorities compare the next field; if that's an uncomparable object, Python raises TypeError. Add an index tiebreaker.
  • Forgetting to negate for a max-heap, or negating only on push.
  • k larger than n, or k = 0.
  • h[0] on an empty heap raises IndexError.
