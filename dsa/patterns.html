The idea

Diagnose before you treat

A doctor doesn't try every medicine. They notice symptoms (fever, rash, cough), match them to a short list of likely conditions, then confirm. Interview problems work the same way: words like "sorted," "top k," "shortest," or "all combinations" are symptoms that point to a short list of techniques.

Decision path

Five questions to ask in order

A mechanic's diagnostic: "Does it start? Is the battery charged? Is there fuel?" Asking the questions in a fixed order narrows the problem fast without guessing.

What's the input shape? Array/string, linked list, tree, graph/grid, or a stream? This picks the page.

Is it sorted, or would sorting help? If yes: two pointers or binary search.

Contiguous range? Sliding window (all positive / "at most k distinct") or prefix sums (negatives, exact sums).

"All" answers, or one best answer? All → backtracking. Best with overlapping choices → DP. Best with a clear greedy choice → sort + greedy or heap.

What does the constraint on n allow? n ≤ 20 → exponential is fine. n ≤ 10⁴ → O(n²) is OK. n ≤ 10⁵+ → you need O(n log n) or O(n). See the Big-O page.

Say the pattern you're considering, and why, before coding: "Because the array is sorted and we need a pair, I'm thinking two pointers." Even if it's wrong, the interviewer can steer you, and your reasoning counts toward the score.
