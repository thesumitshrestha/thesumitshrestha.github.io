Algorithms

Binary search

Binary search is more than finding a number in a sorted array. Its real power is "binary search on the answer": whenever a yes/no check flips from false to true exactly once, you can find the flip point in O(log n).

The idea

Opening a dictionary to the right page

Looking up "kangaroo" in a paper dictionary, you open near the middle, see "M," and know it's in the first half. You open the middle of that half, and so on. A 1,000-page dictionary takes at most 10 openings. That halving is binary search, and it only works because the words are sorted.

Patterns

Five binary search patterns

1. Exact match

O(log n)

Guessing a number between 1 and 100 when the host says "higher" or "lower." Always guess the middle of what's left.

Use whenyou just need to know whether (and where) a value is in a sorted array.

def search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:                      # closed range [lo, hi]
        mid = (lo + hi) // 2
        if nums[mid] == target: return mid
        if nums[mid] < target: lo = mid + 1
        else: hi = mid - 1
    return -1

2. First true (lower bound)

O(log n)

Finding the first bad software release with git bisect: releases go good, good, good, bad, bad. You test the middle release; if it's bad, the first bad one is here or earlier, otherwise later. This is the template you should memorize.

Use whenyou want the first position where a condition becomes true: insert position, first/last occurrence, first bad version.

def first_true(lo, hi, ok):            # ok(x) is False...False True...True
    while lo < hi:                        # half-open: answer in [lo, hi]
        mid = (lo + hi) // 2
        if ok(mid): hi = mid                # mid might be the answer: keep it
        else: lo = mid + 1                  # mid is too early: drop it
    return lo

# Search Insert Position = first index with nums[i] >= target
first_true(0, len(nums), lambda i: nums[i] >= target)
# Same thing, built in:
import bisect
bisect.bisect_left(nums, target)        # first i with nums[i] >= target
bisect.bisect_right(nums, target)       # first i with nums[i] >  target

First and Last Position of an element = bisect_left and bisect_right − 1, checking the element exists.

3. Rotated sorted array

O(log n)

A clock face starting at 4 instead of 12: 4, 5, … 11, 12, 1, 2, 3. Pick any point and at least one side of it still counts up normally. Check which side is "normal," and see if your target is in it.

Use whena sorted array has been rotated (Search in Rotated Sorted Array, Find Minimum).

def search_rotated(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target: return mid
        if nums[lo] <= nums[mid]:                    # left half sorted
            if nums[lo] <= target < nums[mid]: hi = mid - 1
            else: lo = mid + 1
        else:                                         # right half sorted
            if nums[mid] < target <= nums[hi]: lo = mid + 1
            else: hi = mid - 1
    return -1

def find_min(nums):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] > nums[hi]: lo = mid + 1          # min is right of mid
        else: hi = mid
    return nums[lo]

4. Binary search on the answer

O(log range × check cost)

Choosing the slowest reading speed that still finishes a stack of books before your exam. Reading faster always helps, so if speed 20 pages/hour works, 21 works too. Binary search the speed itself, and at each guess just check "do I finish in time?"

Use whenthe problem asks for a min or max value, and you can write a yes/no check that is monotonic: Koko Eating Bananas, Split Array Largest Sum, Capacity to Ship Packages, minimum days.

import math
def min_eating_speed(piles, h):
    def ok(k):                                   # can finish at speed k?
        return sum(math.ceil(p / k) for p in piles) <= h
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid): hi = mid
        else: lo = mid + 1
    return lo

5. Peak finding (search on a slope)

O(log n)

Hiking in fog toward a summit: you can't see the top, but you can feel which way is uphill. Always step uphill and you're guaranteed to reach some peak.

Use whenthe array isn't sorted but comparing neighbors tells you which half must contain an answer (Find Peak Element).

def find_peak(nums):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] < nums[mid + 1]: lo = mid + 1    # uphill to the right
        else: hi = mid
    return lo
Deep analysis

Split Array Largest Sum

Splitting a 10-episode podcast season across k days of listening, keeping episodes in order, so that your longest day is as short as possible. Guess a daily limit; walk through episodes greedily starting a new day when the limit would be exceeded; if that takes more than k days, the limit is too low.

Range: the answer is at least max(nums) (a day must hold the biggest episode) and at most sum(nums) (one day holds everything).

Check: given a limit, greedily count how many groups you need. That's O(n).

Monotonic: a bigger limit never needs more groups. So "groups ≤ k" goes False…False True…True: first-true binary search.

def split_array(nums, k):
    def groups(limit):
        count, cur = 1, 0
        for x in nums:
            if cur + x > limit: count += 1; cur = 0
            cur += x
        return count
    lo, hi = max(nums), sum(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if groups(mid) <= k: hi = mid
        else: lo = mid + 1
    return lo

Complexity: O(n log(sum)). The DP alternative is O(n² · k).

Phrases like "minimize the maximum" or "maximize the minimum" are strong hints for binary search on the answer. Saying so early impresses interviewers.

Before you say "done"

Avoiding the classic bugs

Two people trying to pass in a narrow corridor and both stepping the same way forever: an off-by-one in binary search makes lo and hi stop moving and loop forever.

  • Pick one template and stick with it. With while lo < hi, use hi = mid and lo = mid + 1, never lo = mid (infinite loop when hi = lo + 1).
  • If you need lo = mid (searching for the last true), use mid = (lo + hi + 1) // 2.
  • Test arrays of length 0, 1 and 2, and targets smaller than everything and larger than everything.
  • In Java/C++, write lo + (hi - lo) / 2 to avoid overflow; mention it even in Python.
  • Rotated arrays with duplicates make the worst case O(n); mention it if asked.
