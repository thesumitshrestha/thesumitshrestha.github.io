Sorting

You'll rarely write a sort from scratch in an interview, but you must know how merge sort and quicksort work, what O(n log n) costs, and when sorting first turns a hard problem into an easy one.

The idea

Putting a hand of cards in order

You can sort cards three ways. Insertion: pick up one card at a time and slide it into place (fine for a hand of 7, slow for a deck). Merge: split the deck between friends, each sorts their half, then you merge the two sorted piles by always taking the smaller top card. Quick: pick a card, toss smaller cards left and bigger right, then repeat on each side. The last two are O(n log n), the best possible when you can only compare cards.

Stable means equal items keep their original order. Sort a spreadsheet by city, then (stably) by state, and cities stay alphabetized inside each state. That's why stable sorts matter.

Patterns

Six sorting patterns

1. Merge sort (divide and conquer)

O(n log n) · O(n) space

Two librarians each alphabetize half the returned books, then one merges both carts by always shelving whichever cart's front book comes first.

Use whenyou need a guaranteed O(n log n) stable sort, sorting a linked list, or counting inversions ("how many pairs are out of order") during the merge.

def merge_sort(a):
    if len(a) <= 1: return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]: out.append(left[i]); i += 1   # <= keeps it stable
        else:                  out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

2. Quicksort partition

O(n log n) average

A teacher lining students up by height picks one student as a marker; everyone shorter goes to the left, taller to the right. The marker is now standing exactly where they belong. Repeat in each group.

Use whensorting in place, or in quickselect to find the k-th element in O(n) average (recurse into one side only).

import random
def quickselect(a, k):              # k-th smallest, 0-based
    lo, hi = 0, len(a) - 1
    while True:
        p = random.randint(lo, hi)        # random pivot avoids O(n²) on sorted input
        a[p], a[hi] = a[hi], a[p]
        i = lo
        for j in range(lo, hi):
            if a[j] < a[hi]:
                a[i], a[j] = a[j], a[i]; i += 1
        a[i], a[hi] = a[hi], a[i]         # pivot in final spot
        if i == k: return a[i]
        if i < k: lo = i + 1
        else: hi = i - 1

3. Counting sort / three-way partition

O(n + k)

Sorting laundry into whites, darks and colors: you don't compare shirts with each other, you drop each into its basket. Sort Colors (only 0, 1, 2) is exactly this, done in one pass with three pointers (the Dutch national flag).

Use whenvalues come from a small known range.

def sort_colors(nums):
    lo, i, hi = 0, 0, len(nums) - 1     # [0..lo) = 0s, (hi..] = 2s
    while i <= hi:
        if nums[i] == 0:
            nums[lo], nums[i] = nums[i], nums[lo]; lo += 1; i += 1
        elif nums[i] == 2:
            nums[hi], nums[i] = nums[i], nums[hi]; hi -= 1   # don't move i: recheck swapped value
        else:
            i += 1

4. Sort intervals by start, then sweep

O(n log n)

Booking a meeting room: lay all meetings on a timeline in start order. If a meeting starts before the previous one ends, they overlap and you merge them into one block.

Use whenyou see intervals: merge, insert, count rooms, remove overlaps.

def merge_intervals(iv):
    iv.sort(key=lambda x: x[0])
    out = [iv[0]]
    for s, e in iv[1:]:
        if s <= out[-1][1]:                    # overlaps the last block
            out[-1][1] = max(out[-1][1], e)
        else:
            out.append([s, e])
    return out

5. Custom comparators

O(n log n · compare cost)

Arranging number magnets on a fridge to make the biggest possible number. You don't sort by size; you put "9" before "34" because "934" beats "349". The ordering rule is "which pair reads bigger when glued."

Use whenthe order is defined by a rule between two items rather than a single key (Largest Number).

from functools import cmp_to_key
def largest_number(nums):
    s = list(map(str, nums))
    s.sort(key=cmp_to_key(lambda a, b: (b + a > a + b) - (b + a < a + b)))
    res = "".join(s)
    return "0" if res[0] == "0" else res

# Multi-key with a tuple: by frequency desc, then letter asc
words.sort(key=lambda w: (-cnt[w], w))

6. Sort first, then it's easy

O(n log n) + the easy part

Finding duplicates in a stack of exam papers is painful in random order; sorted by student name, duplicates sit right next to each other. Many problems become a single scan once sorted.

Use whenorder doesn't matter in the output and sorting reveals structure: duplicates, pairs (two pointers), H-Index, meeting rooms, greedy choices.

def h_index(citations):
    citations.sort(reverse=True)
    h = 0
    while h < len(citations) and citations[h] > h:
        h += 1
    return h
Deep analysis

Why comparison sorting can't beat O(n log n)

A game of "20 Questions" where the secret is the correct order of n cards. Each comparison is a yes/no question. There are n! possible orders, and each question at best halves the possibilities, so you need about log₂(n!) questions.

n items have n! possible orderings; the algorithm must be able to produce any one of them.

Each comparison has two outcomes, so k comparisons distinguish at most 2ᵏ orderings. Need 2ᵏ ≥ n!.

So k ≥ log₂(n!), which is about n log₂ n. No comparison sort does better in the worst case.

Counting and bucket sort escape this by never comparing items: they use values as indices. That's why they need a small value range.

"Can you do better than O(n log n)?" is a common follow-up. The answer is "not with comparisons, but yes if values are bounded integers: counting or bucket sort." That's the response they're looking for.

Before you say "done"

Pitfalls

Sorting the guest list for a wedding changes the original list. If someone else still needs the original order, make a copy first.

  • a.sort() sorts in place and returns None; sorted(a) returns a new list.
  • Sorting changes indices. If you need original positions, sort pairs: sorted(enumerate(a), key=…).
  • Quicksort on already-sorted data with a fixed pivot is O(n²). Randomize.
  • Largest Number on [0, 0] must return "0", not "00".
  • Interval problems: ask whether touching intervals like [1,2] and [2,3] count as overlapping.
